Spring 트랜잭션 전파

@Transactional 메서드가 다른 @Transactional 메서드를 부르면 트랜잭션은 하나일까요, 둘일까요. 답은 "전파 속성이 정한다"입니다. 주니어가 가장 자주 밟는 지뢰 두 개와 함께 정리합니다.

전파(propagation)가 뭔가요

트랜잭션이 이미 열려 있는 상태에서 @Transactional 메서드가 또 호출되면 Spring은 선택해야 합니다. 기존 트랜잭션에 올라탈지, 새로 열지, 아니면 에러를 낼지. 이 선택 규칙이 전파 속성입니다. 기본값은 REQUIRED이고, 실무에서 진짜 쓰는 것은 REQUIRED와 REQUIRES_NEW 두 개입니다.

속성기존 트랜잭션이 있을 때없을 때
REQUIRED참여한다새로 시작한다
REQUIRES_NEW기존을 잠시 멈추고 새로 시작한다새로 시작한다
SUPPORTS참여한다트랜잭션 없이 실행한다
MANDATORY참여한다예외를 던진다
NOT_SUPPORTED기존을 멈추고 트랜잭션 없이 실행한다트랜잭션 없이 실행한다
NEVER예외를 던진다트랜잭션 없이 실행한다
NESTED세이브포인트를 만들고 참여한다새로 시작한다

주문은 저장하고, 로그는 실패해도 되는 경우

주문을 만들면서 결제 로그를 남기는 코드입니다. 로그 테이블에 문제가 생겨도 주문까지 취소되면 안 됩니다. 처음 버전은 이랬습니다.

@Service
@RequiredArgsConstructor
public class OrderService {
    private final OrderRepository orderRepository;
    private final PaymentService paymentService;
    private final PaymentLogService paymentLog;

    @Transactional
    public void createOrder(Order order) {
        paymentService.processPayment(order);
        paymentLog.record(order);        // 여기서 예외가 나면?
        orderRepository.save(order);
    }
}

paymentLog.record()가 던진 예외가 createOrder()까지 올라오면 트랜잭션 전체가 롤백됩니다. 로그 한 줄 때문에 결제까지 없던 일이 되는 겁니다. 로그 저장은 REQUIRED로 주문 트랜잭션에 참여하고 있었으니까요.

REQUIRES_NEW로 분리하기

로그를 자기만의 트랜잭션에서 커밋하거나 롤백하게 만들고, 호출하는 쪽은 예외를 잡아서 주문을 계속 진행합니다.

@Service
@RequiredArgsConstructor
public class PaymentLogService {
    private final PaymentLogRepository paymentLogRepository;

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void record(Order order) {
        paymentLogRepository.save(PaymentLog.of(order));
    }
}

try/catch로 감싸지 않으면 REQUIRES_NEW를 붙여도 소용없습니다. 안쪽 트랜잭션은 롤백되지만 예외는 그대로 위로 올라와서 바깥 트랜잭션도 롤백 대상으로 표시되거든요. 전파 속성은 트랜잭션의 경계만 정하지, 예외를 대신 잡아 주지 않습니다.

주니어가 자주 밟는 지뢰 두 개

  • 같은 클래스 안에서 부르면 전파가 일어나지 않습니다. @Transactional은 프록시가 호출을 가로채서 동작하는데, this.record()는 프록시를 거치지 않습니다. 새 트랜잭션이 필요한 메서드는 다른 빈으로 분리하세요.
  • REQUIRES_NEW는 커넥션을 하나 더 씁니다. 바깥 트랜잭션이 잡은 커넥션을 반납하지 않은 채 새 커넥션을 요청합니다. 커넥션 풀이 작으면 여기서 멈추고, 겉으로는 데드락처럼 보입니다. 풀 크기와 동시 요청 수를 같이 보세요.

정리

전파 속성은 "이미 열린 트랜잭션을 어떻게 대할지"의 규칙입니다. 대부분은 기본값 REQUIRED로 충분하고, 바깥 결과와 상관없이 독립적으로 커밋되어야 하는 작업만 REQUIRES_NEW와 try/catch로 분리합니다. 그리고 같은 클래스 안 호출과 커넥션 풀 크기, 이 둘은 꼭 기억하세요.
