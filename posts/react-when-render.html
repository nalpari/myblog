React 렌더링은 언제 일어나는가

"state가 바뀌면 다시 그린다"는 절반만 맞습니다. 컴포넌트가 다시 렌더링되는 조건은 딱 세 가지이고, 그중 하나를 대부분 잊고 있습니다.

렌더링이 일어나는 세 가지 경우

  1. 자기 state가 바뀔 때. setState, useReducer의 dispatch.
  2. 부모가 렌더링될 때. props가 바뀌었든 아니든.
  3. 구독한 context 값이 바뀔 때.

2번이 핵심입니다. 부모가 렌더링되면 자식은 props가 그대로여도 다시 렌더링됩니다. React는 기본적으로 "props가 바뀌었나"를 비교하지 않습니다. 비교하게 만들려면 React.memo가 필요합니다.

function Parent() {
  const [count, setCount] = useState(0);
  return (
    <section>
      <button onClick={() => setCount(count + 1)}>{count}</button>
      <Child />   {/* count와 무관하지만 버튼을 누를 때마다 다시 렌더링된다 */}
    </section>
  );
}

렌더링과 DOM 업데이트는 다릅니다

렌더링은 컴포넌트 함수를 실행해서 "이렇게 보여야 한다"는 결과(엘리먼트 트리)를 만드는 일입니다. React는 그 결과를 이전 결과와 비교해서 달라진 부분만 실제 DOM에 반영합니다. 그러니 렌더링이 자주 일어나도 DOM이 바뀌지 않으면 비용은 함수 실행뿐입니다. 대부분의 컴포넌트는 그 비용이 작아서 최적화가 필요 없습니다.

부모가 다시 그려도 자식이 그려지지 않는 경우

엘리먼트를 props(children)로 받으면, 부모가 렌더링돼도 그 엘리먼트는 같은 객체라서 React가 건너뜁니다.

-function Parent() {
+function Parent({ children }) {
   const [count, setCount] = useState(0);
   return (
     <section>
       <button onClick={() => setCount(count + 1)}>{count}</button>
-      <Child />
+      {children}   {/* 부모가 다시 그려져도 같은 엘리먼트 */}
     </section>
   );
 }

{children}은 Parent 바깥에서 만들어진 엘리먼트입니다. Parent가 다시 실행돼도 그 객체는 그대로이고, React는 같은 참조를 보면 그 서브트리를 건너뜁니다. memo 없이 되는 최적화입니다.

React.memo부터 붙이기 전에, 상태를 아래로 내리거나(state colocation) 자식을 children으로 올릴 수 있는지 먼저 보세요. 구조로 해결되는 문제에 memo를 붙이면 의존성 관리라는 새 문제가 생깁니다.

정리

렌더링 조건은 세 가지, 그중 "부모가 렌더링될 때"를 잊지 마세요. 렌더링과 DOM 업데이트는 다른 일이라 렌더링 횟수 자체는 대부분 문제가 아닙니다. 정말 비싼 자식이 있다면 children으로 올리는 방법을 memo보다 먼저 떠올리세요.
