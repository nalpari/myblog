해시테이블 직접 만들기

Map이 어떻게 O(1)로 값을 찾는지 40줄로 확인합니다. 배열 하나, 해시 함수 하나, 그리고 충돌 처리. 이 셋을 손으로 만들어 보면 면접 질문의 절반이 풀립니다.

핵심 아이디어

키를 숫자(해시)로 바꾸고, 그 숫자를 배열 인덱스로 씁니다. 배열 인덱스 접근은 O(1)이니까, 해시만 빠르면 찾기도 빠릅니다. 해시 함수는 "같은 키면 항상 같은 숫자"이기만 하면 되고, 아래는 문자열용으로 흔히 쓰는 단순한 버전입니다.

function hash(key) {
  let h = 5381;
  for (const ch of String(key)) h = (h * 33) ^ ch.charCodeAt(0);
  return h >>> 0;          // 음수가 되지 않게 부호 없는 32비트로
}

충돌은 반드시 일어난다

배열 칸은 8개인데 키는 무한합니다. 서로 다른 키가 같은 인덱스에 떨어지는 것이 충돌이고, 피할 수 없습니다. 가장 단순한 해결은 체이닝입니다. 각 칸을 리스트로 만들고, 충돌한 키를 그 리스트에 같이 넣습니다.

class HashTable {
  constructor() {
    this.buckets = Array.from({ length: 8 }, () => []);
    this.size = 0;
  }

  set(key, value) {
    const bucket = this.buckets[hash(key) % this.buckets.length];
    const hit = bucket.find(([k]) => k === key);
    if (hit) hit[1] = value;
    else { bucket.push([key, value]); this.size++; }
    if (this.size / this.buckets.length > 0.75) this.resize();
  }

  get(key) {
    const bucket = this.buckets[hash(key) % this.buckets.length];
    const hit = bucket.find(([k]) => k === key);
    return hit ? hit[1] : undefined;
  }
}

get이 O(1)인 이유는 체인이 짧기 때문입니다. 체인이 길어지면 find가 O(n)이 됩니다. 그래서 체인을 짧게 유지하는 규칙이 필요합니다.

왜 0.75에서 두 배로 늘리나

채워진 비율(load factor)이 높아질수록 충돌이 늘고 체인이 길어집니다. 0.75는 메모리 낭비와 충돌 확률 사이의 절충으로, Java의 HashMap도 이 값을 기본으로 씁니다. 늘릴 때 두 배로 늘리는 이유는 비용 때문입니다. resize는 모든 키를 다시 해싱하는 O(n) 작업이지만, 두 배씩 늘리면 이 비용이 삽입 n번에 걸쳐 퍼져서 삽입 한 번의 평균은 O(1)로 유지됩니다.

resize() {
  const old = this.buckets;
  this.buckets = Array.from({ length: old.length * 2 }, () => []);
  this.size = 0;
  for (const bucket of old) for (const [k, v] of bucket) this.set(k, v);
}

정리

  • 해시테이블은 배열과 해시 함수입니다. 해시가 인덱스가 됩니다.
  • 충돌은 피하는 게 아니라 처리하는 것입니다. 체이닝이 가장 단순합니다.
  • load factor 0.75를 넘으면 두 배로 늘려서 체인을 짧게 유지합니다. 그래서 평균 O(1)입니다.
